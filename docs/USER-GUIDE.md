# KReport 사용 설명서

이 문서는 KReport 를 **쓰는 사람**을 위한 것입니다. 설치와 개발은 [README](../README.md) 를 보세요.

권한에 따라 보이는 화면이 다릅니다. 자기 권한에 해당하는 장만 읽으면 됩니다.

| 나의 권한 | 읽을 곳 |
|---|---|
| 리포트를 조회만 함 | [1장](#1-리포트-보기) |
| 리포트를 만들고 고침 | 1장 + [2장](#2-리포트-만들기) |
| 시스템을 관리함 | 전부 + [3장](#3-관리) |

---

## 1. 리포트 보기

### 로그인

기관에서 받은 아이디와 비밀번호로 들어갑니다. 로그인하지 않으면 어떤 화면도 열리지 않습니다.

비밀번호를 모르면 담당 부서에 문의하세요. **세 계정을 여럿이 돌려 쓰지 마세요.** 누가 어떤
자료를 언제 받아 갔는지가 이력에 남는데, 계정을 공유하면 그 기록이 쓸모없어집니다.

### 리포트 찾기

로그인하면 리포트 목록이 나옵니다. 위쪽 검색창에 리포트명이나 ID 일부를 넣고 **조회** 를
누르면 걸러집니다.

목록에서 눈여겨볼 칸이 둘 있습니다.

- **사용** — `중지` 인 리포트는 실행되지 않습니다. 개편 중이거나 폐기된 것입니다.
- **열람** — `🔒 제한` 은 지정된 부서·담당자만 볼 수 있는 리포트입니다. `전체` 는 조회
  권한자 누구나 봅니다.

**목록에 있어야 할 리포트가 안 보인다면** 열람 권한이 없는 것입니다. 관리자에게 요청하세요.
주소를 직접 입력해도 열리지 않습니다.

### 조회 조건 넣고 실행

리포트명을 누르면 뷰어가 열립니다. 왼쪽 위에 조회 조건이 있습니다.

| 조건 종류 | 넣는 법 |
|---|---|
| 날짜 | `2026-01-01` 또는 달력에서 고름 |
| 숫자 | 쉼표를 넣어도 됩니다 (`1,000,000`) |
| 문자 | 일부만 넣고 `%` 를 붙이면 부분 일치 (`복지%`) |

**조회** 를 누르면 리포트가 그려집니다. 조건을 비우면 기본값으로 돕니다.

조회량이 많으면 시간이 걸립니다. 한 번에 최대 5만 행까지 읽습니다. 그보다 많으면 기간을
좁혀 여러 번 나눠 뽑으세요.

### 쪽 넘기기

리포트가 여러 장이면 위쪽에 쪽 번호가 나옵니다. **이전 쪽 / 다음 쪽** 버튼이나 스크롤로
넘깁니다. 스크롤하면 쪽 번호가 따라 움직입니다.

### 파일로 내려받기

오른쪽 위 버튼으로 네 가지 형식을 받을 수 있습니다.

| 형식 | 언제 쓰나 | 특징 |
|---|---|---|
| **PDF** | 결재·보고·인쇄 | 화면에 보이는 그대로. 쪽 나눔·차트·도장 자리까지 동일 |
| **엑셀** | 숫자를 다시 계산해야 할 때 | 본문 행만 담깁니다. 금액·비율이 **숫자 서식**으로 들어가 바로 계산됩니다 |
| **CSV** | 다른 시스템에 넣을 때 | 본문 행만. 서식 없이 값만 |
| **HTML** | 메일 본문·게시판 | 화면과 같은 모양 |

엑셀과 CSV 는 **본문 행만** 담습니다. 머리말·소계·총계 줄은 빠집니다. 표 계산을 다시 할 수
있도록 순수한 데이터만 넘기기 위해서입니다. 소계까지 그대로 필요하면 PDF 를 쓰세요.

파일명은 `리포트명_날짜시각` 으로 자동으로 붙습니다.

## 2. 리포트 만들기

편집 권한이 있어야 합니다. 상단 메뉴의 **디자이너** 로 들어갑니다.

> **편집 권한은 무겁게 다뤄지는 권한입니다.** 리포트 정의에 조회 SQL 을 직접 쓸 수 있고,
> 그것은 곧 연결된 DB 를 읽을 수 있다는 뜻입니다. 권한을 받았다면 그 무게를 알고 쓰세요.

### 리포트는 밴드로 이뤄집니다

한 장을 통째로 그리는 것이 아니라, **역할이 다른 가로 띠(밴드)** 를 쌓아 만듭니다.
데이터 행 수에 따라 본문이 늘어나고 쪽이 저절로 나뉩니다.

| 밴드 | 언제 찍히나 | 주로 넣는 것 |
|---|---|---|
| 리포트 머리말 | 맨 앞 한 번 | 제목, 조회 기간, 출력일시 |
| 페이지 머리말 | 쪽마다 위 | 표 제목 줄 |
| 그룹 머리말 | 그룹이 바뀔 때 | 부서명, 분류명 |
| **본문** | **데이터 한 행마다** | 실제 자료 |
| 그룹 꼬리말 | 그룹이 끝날 때 | 소계 |
| 페이지 꼬리말 | 쪽마다 아래 | 쪽 번호, 기관명 |
| 리포트 꼬리말 | 맨 뒤 한 번 | 총계, 한글 금액, 도장 자리 |

### 만드는 순서

1. **데이터셋** 탭에서 조회 SQL 을 씁니다. `SELECT` 만 됩니다.
2. **필드 가져오기** 를 누르면 결과 컬럼이 왼쪽에 칩으로 나옵니다.
   (이때 데이터를 읽지 않고 컬럼 이름만 확인하므로 빠릅니다.)
3. 칩을 본문 밴드에 끌어다 놓습니다.
4. **미리보기** 로 확인하고 **저장** 합니다.

### 조회 조건 만들기

SQL 안에 `:이름` 을 쓰면 그 자리가 조회 조건이 됩니다.

```sql
select * from budget_execution
 where exec_date between :fromDate and :toDate
   and dept_code like :deptCode
```

그다음 **파라미터** 탭에서 `fromDate`, `toDate`, `deptCode` 의 표시 이름과 형식을 정합니다.
여기 정의하지 않은 이름은 조회 시 무시됩니다.

값을 문자열로 이어 붙이지 않고 따로 바인딩하므로, 사용자가 조건에 무엇을 넣어도 SQL 이
망가지지 않습니다.

### 값 꾸미기 — 표현식

요소의 **값** 칸에 식을 씁니다.

| 쓰고 싶은 것 | 이렇게 |
|---|---|
| 컬럼 값 | `{DEPT_NAME}` |
| 조회 조건 값 | `:fromDate` |
| 계산 | `{BUDGET} - {EXEC_AMT}` |
| 조건 분기 | `IF({RATE} >= 100, '완료', '진행')` |
| 빈 값 대체 | `NVL({NOTE}, '-')` |
| 개인정보 가리기 | `MASK({NAME}, 1, 0)` → `홍**` |
| 금액을 한글로 | `KORNUM({TOTAL})` → `일금 삼천만원정` |
| 소계·총계 | `SUM({AMOUNT})` |
| 쪽 번호 | `{PAGE_NO} / {PAGE_COUNT}` |

쓸 수 있는 함수 전체 목록은 디자이너 오른쪽 **함수** 패널에 호출 형태와 설명이 함께
나옵니다.

### 차트 넣기

요소 종류에서 **차트** 를 고르고, 항목(가로축)과 계열(값)을 정합니다. 아홉 가지가 있습니다.

| 무엇을 보이고 싶은가 | 고를 것 |
|---|---|
| 항목별 크기 비교 | 세로 막대(COLUMN) / 가로 막대(BAR) |
| 시간에 따른 변화 | 꺾은선(LINE) / 영역(AREA) |
| 전체에서 차지하는 몫 | 원(PIE) / 도넛(DONUT) |
| 항목별 구성까지 함께 | 누적 막대(STACKED) |
| 구성비만 비교 | 100% 누적 |

**항목명이 길면 가로 막대**를 쓰세요. 세로 막대는 항목명이 눕거나 잘립니다.

저장할 때 막히는 경우가 있습니다.

- *"계열이 8개입니다. 구분할 수 있는 색이 모자랍니다"* — 사람이 안정적으로 구별하는 색은
  한정되어 있습니다. 차트를 나누거나 항목을 묶으세요.
- *"원 그래프는 계열을 하나만 그립니다"* — 여러 값을 비교하려면 막대를 쓰세요.
- *"로그 축은 꺾은선에서만 쓸 수 있습니다"* — 막대는 길이가 곧 크기라, 로그를 얹으면
  길이 비율이 값 비율과 어긋나 그림이 데이터를 잘못 말하게 됩니다.

### 저장이 안 될 때

저장 전에 정의를 검사합니다. 자주 나오는 것들입니다.

| 메시지 | 뜻 |
|---|---|
| 요소가 인쇄 영역을 넘습니다 | 용지 여백 밖으로 나갔습니다. 왼쪽으로 옮기거나 폭을 줄이세요 |
| 정의되지 않은 그룹을 가리킵니다 | 그룹 꼬리말의 대상 그룹명 오타 |
| 표현식이 올바르지 않습니다 | 괄호나 따옴표가 맞지 않습니다 |
| 이 데이터소스에 조회를 작성할 권한이 없습니다 | 쓸 수 없는 DB 를 가리켰습니다. 관리자에게 문의 |
| 다른 사용자가 먼저 저장했습니다 | 두 사람이 같은 리포트를 열고 있었습니다. 새로 고쳐 다시 작업하세요 |

## 3. 관리

### 리포트별 열람 권한

목록에서 **열람권한** 버튼으로 들어갑니다.

리포트마다 두 상태 중 하나입니다.

- **전체 공개** — 조회 권한자 모두가 봅니다.
- **제한** — 아래 규칙에 걸린 사람만 봅니다.

제한으로 바꾸고 규칙을 답니다. 부서·사용자·권한 중에서 고릅니다.

> **제한인데 규칙이 하나도 없으면 아무도 보지 못합니다.** 규칙을 실수로 지웠을 때 자료가
> 열리는 쪽보다 닫히는 쪽으로 틀리게 한 것입니다.

**관리자와 편집 권한자는 이 통제를 받지 않습니다.** 편집 권한자는 같은 표를 읽는 리포트를
새로 만들 수 있어서, 열람만 막는 것은 통제가 있다는 착각만 줍니다.

사유 칸을 채워 두세요. 감사에서 가장 먼저 묻는 항목입니다.

### 실행 이력

상단 **실행 이력** 에서 누가·언제·어떤 조건으로·몇 건을 받아 갔는지 봅니다.
실행자, 조회 조건, 행 수, 접속지 IP, 소요 시간이 함께 남습니다.

열람이 거부된 시도는 서버 로그에 남습니다.

### 배포 패키지

리포트를 다른 서버(고객사·계열 기관)에 넘길 때 씁니다.

```
[보내는 쪽]  GET /api/deploy/{리포트ID}/package  →  리포트ID.krpt 내려받기
[받는 쪽]    POST /api/deploy/install           →  파일 올리기
```

`.krpt` 는 서명된 파일입니다. **한 글자라도 고치면 설치가 거부됩니다.** 편집기로 열어도
내용이 보이지 않습니다.

패키지를 굽는 것은 개인키가 있는 서버에서만 됩니다. 받는 쪽 서버에는 공개키만 있어서
설치만 할 수 있고 새로 굽지는 못합니다.

### 라이선스

`GET /api/deploy/license` 로 현재 상태를 봅니다. 고객사명, 발급번호, 만료일, 남은 날이
나옵니다.

- 만료 **30일 전부터** 기동할 때마다 경고가 남습니다. 갱신 협의에 시간이 걸리니 그때 바로
  요청하세요.
- 만료되면 리포트 실행이 멈춥니다. 목록은 보이지만 조회가 되지 않습니다.
- 라이선스 파일이 없으면 평가판으로 돌고 출력물에 워터마크가 찍힙니다.

라이선스 파일(`license.key`)은 계약 증표입니다. 백업해 두고, 저장소나 공유 폴더에 올리지
마세요.

## 자주 겪는 일

**리포트가 목록에 없습니다**
열람 권한이 없거나 `중지` 상태입니다. 관리자에게 리포트 ID 를 알려 주고 문의하세요.

**조회하면 "표시할 자료가 없습니다" 만 나옵니다**
조건에 맞는 자료가 없는 것입니다. 기간이나 부서 조건을 넓혀 보세요. 차트가 깨진 것과
구분하려고 일부러 이 문구를 찍습니다.

**PDF 에서 글자가 깨집니다**
서버에 한글 글꼴이 없는 경우입니다. 관리자에게 알리세요.

**엑셀에 소계가 없습니다**
의도된 동작입니다. 본문 행만 담깁니다. 소계까지 필요하면 PDF 를 쓰세요.

**숫자가 엑셀에서 문자로 들어갑니다**
리포트 정의의 표시 형식 문제입니다. 편집 담당자에게 알리세요.

**한참 기다려도 안 나옵니다**
조회량이 많거나 SQL 이 무거운 것입니다. 기간을 좁혀 보고, 그래도 느리면 편집 담당자에게
알리세요. 조회는 정해진 시간이 지나면 자동으로 끊깁니다.

**"이 리포트를 열람할 권한이 없습니다" 가 뜹니다**
목록을 거치지 않고 예전 주소로 들어온 경우입니다. 권한이 필요하면 관리자에게 요청하세요.
