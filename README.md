# KReport — 웹 리포팅 솔루션

UBIReport·크리스탈리포트 계열의 **밴드 기반 웹 리포팅 엔진**입니다.
리포트 정의(JSON)와 조회 조건을 받아 페이지 좌표를 확정하고, 같은 결과를
**HTML / PDF / XLSX / CSV** 네 가지로 내보냅니다. 막대·누적·100% 누적·꺾은선·영역·원·도넛
**차트**를 화면과 PDF에 동일하게 그리고(선형·로그 축), 웹 디자이너와 뷰어를 함께 제공합니다.

- Java 21 / Spring Boot 3.3 / JPA
- 개발 DB: H2(인메모리), 운영: PostgreSQL 프로파일 동봉
- PDF: Apache PDFBox · 엑셀: Apache POI · QR/바코드: ZXing

---

## 1. 빠른 실행

```bash
mvn spring-boot:run
```

| 화면 | 주소 | 설명 |
|---|---|---|
| 리포트 목록 | http://localhost:8080/ | 등록된 리포트 조회·실행 |
| 뷰어 | /viewer/{reportId} | 조회 조건 입력, 쪽 넘김, 내보내기 |
| 디자이너 | /designer/{reportId} | 드래그&드롭 편집, 미리보기, 저장 |
| 실행 이력 | /logs | 누가·언제·무엇을 몇 건 받았는지 |
| H2 콘솔 | /h2-console | JDBC `jdbc:h2:mem:kreport`, 사용자 `sa` (관리자 권한 필요) |

로그인이 필요합니다. 개발용 계정은 `application.yml` 의 `kreport.security` 에 있습니다.

| 계정 | 권한 | 할 수 있는 일 |
|---|---|---|
| `viewer` | 조회 | 리포트 실행, 파일 내려받기 |
| `designer` | 조회 + 편집 | 위 + 리포트 정의 작성·수정, 미리보기 |
| `admin` | 전체 | 위 + 정의 삭제, 실행 이력 열람 |

운영에서는 `kreport.security.in-memory-users=false` 로 두고 기관 인증 체계를 연결합니다
(`prod` 프로파일의 기본값). 내장 계정을 쓰기로 해 놓고 비밀번호를 비워 두면 기동하지 않습니다 —
소스에 박힌 기본 비밀번호가 운영까지 따라가는 일을 막기 위해서입니다.

기동 시 `classpath:reports/*.json` 이 리포트 정의로 자동 등록되고,
업무 샘플 데이터(세출 집행 90건, 민원 53건, 계약 24건)가 적재됩니다.

동봉된 샘플 리포트 세 건:

- **BUDGET_EXEC** 부서별 세출 집행 현황 — 그룹 소계·총계, 집행률, 한글 금액,
  차트 4종(부서별 가로 막대 / 예산과목 도넛 / 월별 추이 꺾은선 / 집행 상태 100% 누적)
- **CIVIL_STATUS** 민원 처리 현황 대장 — 기한 경과 건 강조, 부서별 통계, QR,
  차트 3종(유형별 세로 막대 / 처리 상태 원 그래프 / 부서별 처리 상태 가로 누적 막대)
- **CONTRACT_STATUS** 계약 체결 현황 — 계약방법별 그룹 집계,
  차트 2종(계약방법별 가로 막대 / 계약 규모 분포 **로그 축** 꺾은선)

## 2. 구조

```
template/   리포트 정의 모델 (JSON 직렬화 대상)
engine/
  expression/  자체 표현식 파서·평가기
  data/        데이터셋 조회 (SQL 검증, 이름 바인딩)
  chart/       차트 집계, 축 눈금, 도형 배치, 팔레트
  layout/      밴드 → 페이지 좌표 확정, 그룹 색인, 집계
export/     HTML / PDF / XLSX / CSV 익스포터
domain/     리포트 정의, 실행 이력 (JPA)
service/    정의 관리, 실행, 이력
web/        REST API, 화면 라우팅, 예외 처리
  dto/       응답 레코드
support/    오류 코드, 공통 예외
config/     보안, 설정 바인딩, 함수 묶음 등록
```

`engine/chart` 는 역할별로 나뉩니다. `ChartLayoutEngine` 은 상자를 제목·플롯·범례로
나누기만 하고, 그 안을 `CartesianChartRenderer`(축이 있는 차트)와 `CircularRenderer`
(원·도넛)가 채웁니다. 마크는 `BarRenderer` / `StackedBarRenderer` / `LineRenderer` 가,
축과 라벨은 `AxisRenderer` 가 그립니다. 생김새를 정하는 숫자는 `ChartStyle` 에,
글자 자리를 재는 셈은 `ChartTextMetrics` 에, 값을 좌표로 옮기는 셈은 `Plot` 에 모여 있습니다.

처리 흐름은 한 방향입니다.

```
템플릿 + 조회조건
   → 파라미터 바인딩·검증
   → 데이터셋 조회 (PreparedStatement)
   → 그룹 색인 계산 → 집계 사전 계산
   → 레이아웃 (밴드를 흘려 페이지 분할, 차트는 도형 목록으로)
   → RenderedPage 목록 (좌표 확정)
   → 익스포터 4종
```

익스포터는 좌표가 확정된 결과만 봅니다. 밴드·그룹·표현식 개념이 그 아래로 내려가지 않기 때문에
출력 형식을 하나 더 붙여도 레이아웃 코드를 건드릴 일이 없습니다.

## 3. 리포트 정의

### 밴드

| 종류 | 출력 시점 |
|---|---|
| `REPORT_HEADER` | 최초 1회 |
| `PAGE_HEADER` | 매 쪽 상단 |
| `GROUP_HEADER` | 그룹 시작 시 |
| `DETAIL` | 데이터 행마다 |
| `GROUP_FOOTER` | 그룹 종료 시 |
| `PAGE_FOOTER` | 매 쪽 하단 |
| `REPORT_FOOTER` | 최종 1회 |

좌표 단위는 **pt(1/72인치)** 로 통일했습니다. PDF 좌표계가 pt 기준이라
화면·인쇄·PDF가 같은 자리에 찍힙니다. A4 세로는 595.28 × 841.89pt입니다.

### 요소

`LABEL`(고정 문자열) · `TEXT`(표현식) · `LINE` · `RECT` · `IMAGE` · `BARCODE` · `QRCODE` · `CHART`

### 표현식

| 문법 | 의미 |
|---|---|
| `{컬럼명}` | 현재 행의 값 (대소문자 무관) |
| `@파라미터명` | 조회 조건 값 |
| `PAGE_NO` `PAGE_COUNT` `ROW_NUM` `GROUP_ROW_NUM` `TOTAL_ROWS` `PRINT_DATE` | 내장 변수 |
| `${식}` | 고정 문자열 안의 보간 |

연산자는 `+ - * / %`, 비교 `== != < <= > >=`, 논리 `&& \|\| !`, 삼항 `? :` 를 지원합니다.
덧셈은 양쪽이 숫자면 수치 덧셈, 아니면 문자열 연결입니다.

**집계** — 두 번째 인자로 그룹명을 주면 해당 그룹 범위입니다.

```
SUM({EXEC_AMT})              리포트 전체 합계
SUM({EXEC_AMT}, 'dept')      dept 그룹 소계
COUNT(1, 'dept')             그룹 건수
COUNT({COMPLETED_DATE})      값이 있는 건수 (null 제외)
AVG / MIN / MAX / COUNT_DISTINCT
```

집계는 레이아웃 전에 데이터를 한 번 훑어 확정합니다. 총계를 첫 쪽 머리말에 찍는 리포트가
흔한데, 누적 방식으로는 첫 쪽을 그릴 때 아직 전체 합을 모르기 때문입니다.

**함수** — `IF NVL COALESCE DECODE ISBLANK CONCAT UPPER LOWER TRIM LEN SUBSTR REPLACE
LPAD RPAD MASK ABS ROUND TRUNC FLOOR CEIL TONUMBER TODAY NOW TODATE YEAR MONTH DAY
DATEADD DATEDIFF FORMAT TOSTRING KORNUM`

- `MASK({NAME}, 1, 1)` → `홍*동` — 개인정보 컬럼 가리기
- `KORNUM(SUM({AMT}))` → `일천이백삼만사천` — 금액 한글 병기

수치는 전 구간 `BigDecimal`로 다룹니다. 금액 집계에서 `double` 누적 오차는
그대로 결산 불일치가 되기 때문입니다.

### 차트

`CHART` 요소는 **놓인 밴드가 곧 집계 범위**입니다. 리포트 꼬리말에 두면 전체를,
그룹 꼬리말에 두면 그 그룹의 행만 집계합니다. 범위를 따로 고르게 하지 않은 이유는,
"어느 데이터를 그린 건지"가 정의와 화면 사이에서 어긋나는 일을 막기 위해서입니다.

| 종류 | 쓰임 | 계열 상한 | 항목 상한 |
|---|---|---|---|
| `COLUMN` | 항목별 크기 비교 | 8 | 20 |
| `BAR` | 항목명이 길 때(부서명, 사업명) | 8 | 20 |
| `STACKED_COLUMN` | 항목별 합계 + 그 안의 구성 | 6 | 20 |
| `STACKED_BAR` | 위와 같되 항목명이 길 때 | 6 | 20 |
| `PERCENT_COLUMN` | 총량을 지우고 구성비만 비교 | 6 | 20 |
| `PERCENT_BAR` | 위와 같되 항목명이 길 때 | 6 | 20 |
| `LINE` | 시간 흐름 | 8 | 60 |
| `AREA` | 시간 흐름 + 누적감 | 4 | 60 |
| `PIE` / `DONUT` | 한눈에 보는 구성비 | 1 | 6 |

누적은 계열 상한이 낱개 막대보다 낮습니다. 조각이 맞붙어 있어 경계를 구별해야 하는데,
조각이 많아지면 가운데 것들이 얇아져 색도 값도 읽히지 않습니다.

```json
{
  "type": "CHART", "x": 0, "y": 48, "width": 306, "height": 150,
  "chart": {
    "type": "BAR",
    "title": "부서별 집행액",
    "categoryExpression": "{DEPT_NAME}",
    "series": [{ "name": "집행액", "expression": "{EXEC_AMT}", "aggregation": "SUM" }],
    "sort": "VALUE_DESC", "showValues": true, "valueFormat": "#,##0"
  }
}
```

집계는 `SUM AVG COUNT MIN MAX`. 항목과 값 모두 표현식이라 **SQL을 고치지 않고도**
집계 축을 바꿀 수 있습니다. 월별 추이는 조회 쿼리를 그대로 두고 이렇게 만듭니다.

```
categoryExpression: FORMAT({EXEC_DATE},'MM') + '월'
sort: CATEGORY_ASC
```

**누적 막대**도 같은 이유로 SQL 피벗이 필요 없습니다. 조건식으로 0/1을 만들어 합치면
그대로 조건부 건수가 됩니다.

```json
{
  "type": "STACKED_BAR",
  "categoryExpression": "{DEPT_NAME}",
  "series": [
    { "name": "처리완료", "expression": "{STATUS} == '처리완료' ? 1 : 0", "aggregation": "SUM" },
    { "name": "처리중",   "expression": "{STATUS} == '처리중' ? 1 : 0",   "aggregation": "SUM" },
    { "name": "반려",     "expression": "{STATUS} == '반려' ? 1 : 0",     "aggregation": "SUM" }
  ],
  "sort": "VALUE_DESC", "showValues": true
}
```

타입만 `PERCENT_BAR` 로 바꾸면 **100% 누적**이 됩니다. 항목마다 길이를 100%로 맞춰
총량 차이를 지우고 구성만 비교합니다. 동봉된 세출 리포트가 그 쓸모를 보여 줍니다 —
환경관리과는 집행액이 가장 적지만(4.2억) 집행완료율은 91%로 가장 높은데,
절대량 막대만 보면 드러나지 않는 사실입니다.

다만 총량을 지우는 것이 이 그림의 목적이자 위험입니다. 3건을 나눈 비율과 300건을 나눈
비율이 똑같은 막대로 보이므로, 막대 끝에는 늘 원래 합계를 함께 적습니다.

**로그 축**은 값이 몇 자릿수씩 차이 나는 데이터에서 씁니다. `valueScale` 을 `LOG` 로
두면 같은 배수가 같은 거리에 놓여, 선형 축에서 바닥에 깔려 버리던 작은 값들도 함께 읽힙니다.

```json
{ "type": "LINE", "valueScale": "LOG", "valueFormat": "#,##0" }
```

동봉된 계약 리포트가 그 예입니다. 계약금액이 90만 원(소액수의계약)부터 14억 원(대형 공사)까지
1,500배 넘게 벌어지는데, 선형 축이면 상위 몇 건을 뺀 나머지가 모두 바닥에 붙어 분포를 읽을 수
없습니다. 로그 축에서는 24건이 고른 곡선으로 늘어서 금액대별 구성이 한눈에 들어옵니다.

**꺾은선에서만 쓸 수 있습니다.** 막대는 길이가 곧 크기라서 로그를 얹으면 길이 비율이
값 비율과 달라지고, 애초에 기준선 0이 로그 축에 존재할 수 없습니다. 원 그래프는 조각 각도가,
영역 차트는 채움 면적이 같은 이유로 왜곡됩니다. 다른 종류에 `LOG` 를 설정하면
저장 단계에서 막습니다. 설정이 맞더라도 데이터에 0이나 음수가 섞여 있으면 로그값 자체가
없으므로 선형으로 되돌려 그립니다 — 빈 차트를 내놓는 것보다 낫습니다.

눈금은 10의 거듭제곱에 놓고, 자릿수 폭이 좁으면 그 사이에 2와 5의 배수를 더 넣습니다.
거듭제곱만으로는 범위가 좁을 때 눈금이 두어 개밖에 남지 않기 때문입니다.

읽히는 그림이 되도록 엔진이 강제하는 규칙이 몇 가지 있습니다.

- **계열 색은 고정 순서로 배정하고 순환시키지 않습니다.** 9번째 계열에 색을 새로
  만들어 붙이면 그때까지 지켜 온 구분 보장이 깨지므로, 상한을 넘는 항목은 색을 늘리는 대신
  값이 큰 것부터 남기고 나머지를 "기타"로 묶습니다. 기본 팔레트는 인접 계열 간
  색각 이상 분리도와 정상 시야 분리도를 모두 통과하도록 순서가 정해져 있습니다.
- **막대의 기준선은 항상 0입니다.** 0이 아닌 값에서 축을 끊으면 막대 길이의 비율이
  실제 값의 비율과 달라져 차이가 실제보다 크게 보입니다.
- **값 서식에 소수 자리가 없으면 눈금도 정수로 놓습니다.** 건수 12를 5칸으로 나누면
  2.5 간격이 잡히는데, 이걸 정수로 찍으면 `0·3·5·8·10`이 되어 간격이 들쭉날쭉해 보입니다.
- **계열이 둘 이상이면 범례가 항상 붙고**, 한 줄에 안 들어가면 다음 줄로 넘깁니다.
  잘라 내면 그 색이 무엇인지 알 방법이 없어져 범례를 붙인 이유가 사라집니다.
  범례 여부는 정의가 아니라 실제로 그려질 데이터의 계열 수로 판단합니다.
- **`showValues`를 켜도 꺾은선은 끝점 하나만 적습니다.** 모든 점에 숫자를 붙이면 읽히지 않습니다.
- **누적은 축 범위를 항목별 합계로 잡습니다.** 개별 최댓값으로 잡으면 쌓인 막대가 축을 넘어 잘립니다.
  양수와 음수는 기준선을 사이에 두고 각각 위아래로 쌓습니다. 섞어서 더하면 조각 길이가
  실제 값과 무관해져 그림이 데이터를 설명하지 못하게 됩니다.
- **100% 누적의 축은 0~100%로 고정**되고 눈금은 값 서식 대신 퍼센트로 적습니다.
  조각에는 비율을, 막대 끝에는 길이를 맞추느라 지워진 원래 합계를 적습니다.
  구성비를 보는 그림이라 음수 계열은 그리지 않고, 합계가 0인 항목은 건너뜁니다.
- **누적 조각의 값은 조각 안에 들어갈 때만 적고**, 막대 끝에는 합계를 적습니다.
  조각 안 글자색은 바탕 밝기에 따라 흰색과 잉크색 중에서 고릅니다. 한쪽으로 고정하면
  팔레트에 노랑과 보라가 함께 있는 이상 어느 한 계열의 값이 반드시 안 보이게 됩니다.
- **가로 축의 눈금 숫자는 자리가 모자라면 몇 개씩 건너뛰며 찍습니다.** 금액처럼 자릿수가 긴
  값을 좁은 폭에 넣으면 숫자끼리 밀어내 아무것도 못 읽게 됩니다. 눈금선 자체는 다 그립니다.
- 눈금선은 지면보다 한 단계만 어두운 실선 헤어라인, 마크 사이는 테두리 대신 2px 지면 간격,
  막대는 값이 끝나는 쪽 모서리만 둥글립니다(기준선 쪽까지 둥글리면 축에서 떠 보입니다).
- 글자는 계열색이 아니라 잉크색으로 씁니다. 색은 옆의 표식이 나릅니다.

차트는 HTML에서 인라인 SVG로, PDF에서 PDFBox 도형으로 그려집니다. 같은 도형 목록을
양쪽이 각자 그리므로 화면과 인쇄물이 어긋나지 않습니다. 엑셀·CSV로 내보낼 때는 빠집니다
(표 추출이 본문 밴드만 보기 때문에 자동으로 제외됩니다).

### 데이터셋

```sql
select dept_code, dept_name, exec_amt
  from budget_execution
 where fiscal_year = :fiscalYear
   and dept_code like :deptCode
 order by dept_code, exec_date
```

`:이름` 은 `PreparedStatement` 로 바인딩합니다. 값을 SQL 문자열에 끼워 넣지 않으므로
조회 조건 입력란이 주입 통로가 되지 않습니다. 문자열 리터럴·주석·PostgreSQL 캐스트(`::`)
안쪽은 바인딩으로 보지 않습니다.

정렬은 SQL이 책임집니다. 엔진은 **인접한 동일 키**를 한 그룹으로 봅니다.

## 5. 확장 지점

엔진 코드를 고치지 않고 늘릴 수 있는 자리입니다. 기관마다 필요한 것이 다른데 그때마다
엔진에 손을 대면, 엔진이 특정 기관의 사정을 알게 되고 다음 납품 때 그 코드를 들어내야 합니다.

### 표현식 함수

`FunctionLibrary` 를 구현한 스프링 빈을 올리면 기동할 때 함께 등록됩니다.

```java
@Component
class FiscalFunctions implements FunctionLibrary {

    @Override public String name() { return "회계연도"; }

    @Override public List<ReportFunction> functions() {
        return List.of(ReportFunction.of("FISCALYEAR", 1,
                "FISCALYEAR(날짜)", "3월에 시작하는 회계연도",
                args -> {
                    LocalDate d = Values.toLocalDate(args.get(0));
                    return BigDecimal.valueOf(d.getMonthValue() >= 3 ? d.getYear() : d.getYear() - 1);
                }));
    }
}
```

인자 개수는 선언에 적어 두면 레지스트리가 호출 직전에 한 곳에서 검사합니다. 같은 선언이
디자이너의 함수 도움말(`GET /api/reports/functions`)로도 그대로 나갑니다.

두 가지는 막혀 있습니다. **내장 함수와 이름이 겹치면 등록을 거부**하고, **기동이 끝나면
목록을 잠급니다**. 같은 표현식이 어느 서버에 올렸느냐에 따라, 또는 언제 실행했느냐에 따라
다른 값을 내면 그 리포트로는 결재를 올릴 수 없기 때문입니다.

### 여러 DB 연결 (거래처·계열 기관)

리포트마다 어느 DB 에 물어볼지 정할 수 있습니다. `dataSet.dataSource` 에 이름을 적으면
되고, 비우면 기본 연결(`main`)입니다.

```yaml
kreport:
  datasources:
    partner-a:
      url: jdbc:postgresql://partner-a-db:5432/orders
      username: kreport_ro
      password: ${PARTNER_A_DB_PASSWORD}
      read-only: true        # 기본값. 드라이버 차원에서 조회만 허용
      max-pool-size: 5
      writers:               # 이 DB 를 향한 쿼리를 쓸 수 있는 사람
        users: [partner-a-editor]
  security:
    main-writers:            # 우리 업무 DB 는 내부 직원만
      roles: [INHOUSE]
```

**`writers` 를 적지 않으면 아무도 그 DB 에 쿼리를 쓰지 못합니다.** 새로 붙인 연결이
기본으로 열려 있으면, 추가한 사실을 모르는 사이에 편집 권한자 전원이 그 DB 를 읽게 됩니다.
`main` 만 예외로, 비어 있으면 종전대로 편집 권한자 모두에게 열립니다 — 이 기능을 켜는
것만으로 기존 편집이 멈추지 않게 한 것입니다. 외부 데이터소스를 등록했는데 `main-writers`
가 비어 있으면 기동할 때 경고를 남깁니다.

접속 정보는 환경변수로 받으세요. 설정 파일에 평문으로 두면 운영 서버에 접근할 수 있는
사람이 거래처 DB 계정을 갖게 됩니다.

### 소속 부서 조회

`ViewerDirectory` 를 구현한 빈을 올리면 리포트별 열람 권한이 그 소속 정보를 씁니다.
부서를 어디서 가져오는지는 기관마다 다릅니다 — 인사 연계, SSO 토큰의 클레임, LDAP 속성.
엔진이 그중 하나를 알게 되면 다음 기관에서 그 코드를 들어내야 하므로 인터페이스로 뺐습니다.

```java
@Component
class HrViewerDirectory implements ViewerDirectory {
    @Override public Viewer lookup(String username, Set<String> roles) {
        return new Viewer(username, hrClient.departmentsOf(username), roles);
    }
}
```

빈을 올리지 않으면 설정 파일을 읽는 기본 구현이 쓰입니다.

```yaml
kreport.security.departments:
  viewer: "1100"
  kim: "1100,2100"   # 겸직은 쉼표로
```

### 출력 형식

`ExportFormat` 에 항목을 더하고 `ReportExporter` 를 구현합니다. 익스포터는 좌표가
확정된 `RenderedPage` 만 보므로 밴드·그룹·표현식을 몰라도 됩니다.

### 데이터 출처

`DataSetProvider` 구현을 늘리면 SQL 이 아닌 곳(연계 API, 파일)에서도 데이터를 받을 수
있습니다. 조회 결과를 `DataTable` 로만 돌려주면 그 뒤의 집계·레이아웃은 그대로 돕니다.

### 오류 코드

`ErrorCode` 에 항목을 더하고 `KReportException` 을 상속합니다. 예외 처리기는 타입 하나로
가르므로 처리기를 따로 늘리지 않아도 됩니다. 응답의 `code` 는 연계 기관과의 계약이라,
문구를 다듬어도 값은 그대로 둡니다.

```json
{
  "timestamp": "2026-09-27T13:31:02.5",
  "status": 400,
  "code": "PRM-400",
  "message": "조회 조건이 올바르지 않습니다.",
  "details": ["회계연도 값을 입력하세요."]
}
```

## 6. 설계에서 신경 쓴 지점

**두 번 나눠 그리는 레이아웃** — 1차로 본문을 흘려 쪽을 나누고, 전체 쪽 수가 확정된
뒤 2차로 머리말·꼬리말을 얹습니다. 꼬리말의 `1 / 12` 표기가 바로 그 값을 필요로 하는데,
한 번에 그리면 마지막 쪽에 닿기 전까지 그 값을 알 수 없습니다.

**엑셀은 표로 내보낸다** — 좌표를 셀에 1:1로 옮기면 병합 셀 범벅이 되어 받는 쪽에서
정렬도 합계도 못 냅니다. 본문 밴드의 요소 배치를 컬럼으로 보고 표를 복원하며,
행을 고를 때는 좌표가 아니라 **요소의 출처 밴드**를 봅니다. 좌표로 추리면 컬럼과 같은 자리에
놓인 머리말 라벨이나 소계 칸이 데이터로 딸려 들어갑니다. 숫자는 문자열이 아니라 수치 셀로 넣고,
화면에서 퍼센트로 보이던 칸은 엑셀 서식도 퍼센트로 맞춥니다.

**표현식에 SpEL을 쓰지 않음** — 리포트 정의는 운영 중 화면에서 편집되는 자산입니다.
SpEL은 임의 메서드 호출이 가능해 편집 권한이 곧 코드 실행 권한이 됩니다. 등록된 함수만
부를 수 있는 파서를 직접 두었고, SQL도 `SELECT`/`WITH` 만 통과시킵니다.

**정의는 JSON 한 덩어리로 저장** — 밴드와 요소를 테이블로 펼치면 저장마다 delete-insert가
되고 구조가 바뀔 때마다 마이그레이션이 필요합니다. 통째로 읽고 통째로 쓰는 문서형 데이터라
그대로 둡니다. 대신 낙관적 잠금(`@Version`)을 걸어 두 사람이 디자이너를 함께 열었을 때
뒤에 저장한 쪽이 앞사람 작업을 조용히 덮어쓰지 않게 했습니다.

**실행 이력은 별도 트랜잭션** — 리포트는 업무 데이터를 대량으로 꺼내 파일로 내보내는
통로입니다. 실패했다는 사실도 남아야 하므로 `REQUIRES_NEW` 로 분리했고,
같은 빈에서 자기호출하면 프록시를 타지 않아 전파 설정이 무시되므로 빈 자체를 나눴습니다.

**PDF 한글** — 표준 14 폰트에는 한글 글리프가 없습니다. `classpath:fonts/` → OS 기본 경로
순으로 TTF를 찾아 서브셋 임베딩하고, 못 찾으면 기동 시 경고를 남깁니다.
글리프가 없는 문자 하나 때문에 출력 전체가 실패하지 않도록 치환 처리도 넣었습니다.
같은 이유로 샘플의 글머리 표식은 `▪` 같은 기호 문자가 아니라 도형으로 그립니다
(맑은고딕에 그 글리프가 없어 PDF에서 `?`로 떨어집니다).

**축은 한 겹으로 감싼다** — 선형·로그·퍼센트의 차이는 `ValueAxis` 구현 안에만 있고,
마크를 놓는 쪽은 축 종류를 모릅니다. 눈금 계산과 좌표 변환이 축마다 흩어지면
한쪽만 고쳐져 눈금과 마크가 어긋나는데, 그 어긋남은 숫자를 직접 대보기 전까지 보이지 않습니다.

**차트는 도형 목록까지만 만든다** — 차트 로직은 축 계산과 마크 배치를 끝낸
도형 목록을 내놓고 멈춥니다. HTML은 그것을 SVG로, PDF는 PDFBox 명령으로 각자 그립니다.
형식마다 차트를 다시 짜면 화면과 인쇄물이 조금씩 어긋나기 시작하는데, 그 어긋남은
출력물을 나란히 놓고 보기 전까지 드러나지 않습니다. 글자 베이스라인 계산도
SVG의 `dominant-baseline`에 맡기지 않고 같은 식을 양쪽이 쓰게 했습니다.

**정의 검증은 저장 시점에** — 그룹명 오타, 깨진 표현식, 인쇄 영역을 넘는 요소처럼
정적으로 잡히는 것은 위치와 함께 저장 단계에서 알려 줍니다. 실행 중에 터지면 원인을 짚기 어렵습니다.

## 7. 접근 통제

**권한은 화면이 아니라 할 수 있는 일로 나눕니다.** 핵심은 조회와 편집의 분리입니다.
리포트 정의를 저장할 수 있다는 것은 조회 SQL 을 마음대로 쓸 수 있다는 뜻이고,
그것은 곧 업무 DB 전체를 읽을 수 있다는 뜻입니다. 목록을 볼 수 있다고 정의를 고칠 수 있으면
열람 범위 통제가 통째로 무의미해집니다.

| 경로 | 필요 권한 |
|---|---|
| `/`, `/viewer/**`, `GET /api/reports/**` | 조회 |
| `POST /api/reports/*`, `/validate`, `/preview`, `/fields`, `/designer/**` | 편집 |
| `DELETE /api/reports/**`, `/logs`, `/h2-console/**`, `/access/**` | 관리자 |

### 리포트별 열람 권한

기능 단위 권한 위에, **조회 권한자들 사이의 범위**를 리포트마다 나눕니다. 인사·감사 자료를
전 직원이 아니라 담당 부서만 보게 하는 것이 목적입니다.

리포트는 `PUBLIC`(기본) 또는 `RESTRICTED` 입니다. 제한이면 부서·사용자·권한 규칙에 걸린
사람만 봅니다. **제한인데 규칙이 하나도 없으면 아무도 보지 못합니다** — 규칙을 실수로
지웠을 때 자료가 열리는 쪽보다 닫히는 쪽으로 틀리게 한 것입니다.

막는 자리는 목록 하나가 아닙니다. 목록에서 가리는 것과 주소를 직접 치는 것은 다른 문제라,
실행·내보내기·조회조건 메타·**정의 원본**까지 모두 검사합니다. 정의 원본을 포함한 이유는
그 안에 조회 SQL 이 들어 있어서, 리포트를 못 보는 사람이 그 리포트가 어떤 표를 어떤
조건으로 읽는지 알 수 있다면 통제에 구멍이 남기 때문입니다. 열람이 거부되면 누가 무엇을
보려 했는지 로그에 남습니다.

**관리자와 편집 권한자는 이 통제를 받지 않습니다.** 편집 권한자는 같은 표를 읽는 리포트를
새로 만들 수 있어, 열람만 막는 것은 통제가 있다는 착각만 줍니다. 편집 권한 자체를 DB 열람
권한과 같은 무게로 주는 것이 실제 방어선이고, 이 설계는 그 사실을 감추지 않습니다.
열람 범위를 정하는 일은 리포트를 만드는 사람이 아니라 관리자에게 두었습니다. 만든 사람이
스스로 범위를 넓힐 수 있으면 승인 절차가 형식이 됩니다.

소속 부서는 `ViewerDirectory` 로 가져옵니다(「5. 확장 지점」).

### 밖의 사람에게 편집을 열어 줄 때

거래처 담당자에게 편집 권한을 주는 경우입니다. **편집 권한은 곧 임의 SELECT 를 쓸
권한**이라, 데이터소스를 나누지 않으면 그 사람이 우리 업무 DB 를 통째로 읽을 수 있습니다.
리포트별 열람 권한으로도 막지 못합니다 — 편집 권한자는 그 통제를 받지 않기 때문입니다.

그래서 연결을 늘리는 일과 접근을 나누는 일을 한 묶음으로 두었습니다. 데이터소스마다
`writers` 를 적고, 다음 세 자리에서 확인합니다.

| 자리 | 왜 |
|---|---|
| 정의 저장 | 어느 DB 로 질의를 보낼지 확정되는 자리 |
| 미리보기 (`/preview`) | 저장하지 않고 임의 SQL 이 실행되는 경로 |
| 컬럼 탐색 (`/fields`) | 마찬가지로 저장을 거치지 않고 SQL 이 실행됨 |

저장만 막으면 저장하지 않고 미리보기만 돌려 남의 DB 를 읽을 수 있습니다.
데이터소스 이름을 적지 않으면 `main` 으로 가므로, 생략해도 우회가 되지 않습니다.

그 밖에 적용한 것들:

- **감사 이력에 실제 사용자명**을 남깁니다. 누가 어떤 조건으로 몇 건을 받아 갔는지 모르는
  이력은 없는 것과 같습니다. 실행자·조회조건·행수·IP·소요시간을 함께 기록합니다.
- **CSRF 토큰**을 쿠키로 내리고 헤더로 되돌려 받습니다. 남의 사이트가 로그인된 브라우저를
  빌려 정의를 고치거나 데이터를 받아 가지 못합니다.
- **IMAGE 원본은 허용된 위치에서만** 읽습니다. 기본은 classpath 안쪽뿐입니다. 주소를 열어 두면
  정의를 쓰는 사람이 서버를 통해 내부망에 요청을 보낼 수 있고(SSRF), 파일 경로를 열어 두면
  서버 파일을 이미지로 읽어 낼 수 있습니다. 리다이렉트도 따라가지 않습니다.
- **오류 메시지에 내부 사정을 싣지 않습니다.** JDBC 드라이버 메시지에는 테이블명과 컬럼명이
  그대로 들어 있어, 조회 조건을 바꿔 가며 스키마를 훑을 수 있습니다. 원인은 서버 로그로만 봅니다.
- **내보내기는 두 단계**입니다. 조건 검증·조회·레이아웃을 응답에 손대기 전에 끝냅니다.
  스트림을 한 번 열면 상태 코드도 헤더도 바꿀 수 없어서, 그 뒤에 오류가 나면
  받는 쪽이 깨진 파일을 받게 됩니다.
- CSP, `frame-ancestors 'none'`, 세션 고정 방지, 로그인 시 세션 재발급.

기관 인증 체계(SSO, GPKI 등)를 붙일 때는 `UserDetailsService` 구현만 갈아 끼우면 됩니다.
경로별 권한 규칙은 그대로 씁니다.

## 8. 테스트

```bash
mvn test
```

156건. 표현식 파서·평가(28), 차트 집계·축·배치·누적·로그·라벨배치(45),
SQL 가드와 이름 바인딩(13), **접근 통제(12)**, **리포트별 열람 권한(11+11)**,
**데이터소스 격리(9)**, 레이아웃(8), 익스포터(8), 함수 레지스트리(7),
템플릿 캐시 규약(3), 서식 동시성(1)을 덮습니다.

`DataSourceIsolationTest` 는 거래처 DB 를 별도 H2 로 띄우고, 거래처 편집자가
데이터소스 이름만 바꿔 우리 DB 를 읽는 정의를 저장하려 하면 거부되는지 확인합니다.

접근 통제 시험은 권한 경계에 못을 박아 둔 것입니다. 조회 권한으로 정의를 고치거나
임의 SQL 의 컬럼을 들여다볼 수 없는지, 편집 권한으로 정의를 지우거나 이력을 볼 수 없는지,
CSRF 토큰 없는 쓰기가 거부되는지, 오류 메시지에 테이블명이 섞여 나오지 않는지를 확인합니다.
PDF 테스트는 실제로 PDF를 만들어 `PDFTextStripper` 로 한글이 살아 있는지 확인하고,
한글 TTF가 없는 환경에서는 건너뜁니다. 차트 테스트에는 모든 도형이 차트 상자 안에
들어오는지 검사하는 항목이 있어, 라벨이 잘리거나 넘치는 회귀를 잡습니다.

`TemplateCacheContractTest` 는 리포트를 실제로 실행해 보고 캐시에 올라간 템플릿이
그대로인지 확인합니다. 실행 경로는 속도 때문에 캐시 인스턴스를 그대로 쓰는데, 거기서
템플릿을 한 번이라도 고치면 그 뒤로 같은 리포트를 뽑는 모든 사람의 출력물이 조용히
달라집니다. 컴파일러가 막아 주지 못하는 약속이라 시험으로 못을 박아 둔 것입니다.

## 9. 운영 배포

```bash
mvn clean package
java -jar -Dspring.profiles.active=prod \
     -DDB_USER=kreport -DDB_PASSWORD=**** \
     target/kreport-1.0.0.jar
```

`prod` 프로파일은 PostgreSQL을 바라보고 `ddl-auto: validate`, 샘플 데이터 적재 없음,
Thymeleaf 캐시 사용, H2 콘솔 비활성입니다.

한글 폰트를 고정하려면:

```yaml
kreport:
  font:
    regular: /usr/share/fonts/truetype/nanum/NanumGothic.ttf
    bold: /usr/share/fonts/truetype/nanum/NanumGothicBold.ttf
```

또는 `src/main/resources/fonts/NanumGothic.ttf` 에 넣어 함께 패키징합니다.

- **행 수준 보안** — 같은 리포트라도 자기 부서 자료만 보이게 하려면 데이터셋에 조직 조건을
  강제로 끼워 넣는 계층이 필요합니다. 지금은 정의에 적은 SQL 이 그대로 나갑니다.
- **비밀번호 정책과 계정 잠금** — 내장 계정은 개발용이라 시도 횟수 제한이 없습니다.
  기관 인증 체계를 붙이면 대개 그쪽이 맡습니다.
- **이중 축은 넣지 않습니다** — y축이 둘이면 같은 그림에서 서로 다른 척도를 비교하게 되어
  실제로는 없는 상관관계가 보입니다. 두 측정값은 차트를 나누거나 공통 기준으로 지수화하세요.
- **가변 높이 밴드** — 현재 밴드 높이는 고정입니다. 긴 텍스트를 담으려면 내용에 따라
  늘어나는 밴드와 그에 맞춘 쪽 분할 재계산이 필요합니다.
- **서브리포트**, **크로스탭(피벗)**
- **대용량 비동기 출력** — 현재는 동기 처리에 조회 상한 5만 행입니다.
